# v1.1 迭代计划：设置面板 + 多屏快捷切换

## 背景

v1.0 已实现单一热键 `⌘⌃→` 把鼠标移到下一块屏幕。v1.1 增加**设置面板**，支持按屏幕排列配置两类快捷键：
- **方向键**：按物理排列跳到左/右/上/下相邻屏幕。
- **每屏直达**：给每块屏单独分配一个快捷键，直接跳到该屏。

## 需求确认（已与用户确认）

- 切换方式：**方向键 + 每屏直达都要**，都可配置。
- 设置面板：**可视化排列图**（类似系统「显示器排列」，按真实位置画屏幕缩略图，点击屏幕配置其直达快捷键）。
- 快捷键录入：**下拉选择**（修饰键组合下拉 + 主键下拉），非录制式。

## 设计

### 配置模型（持久化到 UserDefaults，JSON 编码）

```
struct KeyCombo: Codable, Equatable {
    var modifiers: UInt64   // CGEventFlags 相关位
    var keyCode: Int64
}

struct AppConfig: Codable {
    var directionalEnabled: Bool          // 方向键总开关
    var directionalModifier: UInt64       // 方向键共用的修饰键组合（配 ←→↑↓）
    var directEnabled: Bool               // 每屏直达总开关
    var directBindings: [Int: KeyCombo]   // 屏幕排列序号(0基) -> 快捷键
}
```

- **屏幕身份用「排列序号」标识**（左→右、上→下排序后的 index）。排列变化时按新序号重映射，简单且稳健，契合「根据屏幕排列」。
- 默认：方向键开启、修饰键 `⌘⌃`（沿用 v1.0 手感，`⌘⌃→` 仍是向右）；每屏直达默认关闭，待用户分配。

### 屏幕几何与方向切换

- `ScreenLayout`：封装 `CGGetActiveDisplayList` + `CGDisplayBounds`，输出按排列排序的屏幕数组（含 index、bounds、center）。
- 方向切换：从当前屏中心，向目标方向找「最近的相邻屏」——该方向上投影为正、且垂直偏移最小者。找不到则不动作。
- 直达切换：直接取 `directBindings[index]` 对应屏，移到其中心。
- 复用现有 `MouseMover` 的「移动到指定屏中心」逻辑，抽出 `move(to display:)`。

### 热键匹配（重构 HotkeyManager）

- 由「单一硬编码组合」改为「按当前 `AppConfig` 匹配一组绑定」。
- 每次 keyDown：先算出事件的 (修饰键子集, keyCode)；
  - 若方向键启用且修饰键==directionalModifier 且 keyCode∈{←124,→123?,↑,↓}→ 触发对应方向（注意：←123 →124 ↑126 ↓125）。
  - 否则遍历 directBindings 找匹配 → 触发直达。
  - 命中则吞掉事件。
- 配置变更后热键即时生效（HotkeyManager 持有 config 引用/回调重载）。

### 设置面板（AppKit，无 Storyboard，纯代码）

- 菜单栏新增「设置…」，打开一个 `NSWindow`。因 App 是 `.accessory`，打开前 `NSApp.activate(ignoringOtherApps:true)` 让窗口可交互。
- **ArrangementView**（自定义 `NSView`）：把所有屏 bounds 等比缩放绘制成缩略图矩形，标注序号；点击选中某屏高亮。
- 右侧/下方控件：
  - 方向键区：启用开关 + 修饰键组合下拉（`⌘⌃` / `⌘⌥` / `⌃⌥` / `⌘⌃⌥` / `⌘⌥⇧` …）。
  - 每屏直达区：启用开关；选中屏后显示「修饰键下拉 + 主键下拉（1–9 / A–Z / F1–F12）」，可清除。
  - 冲突检测：保存时若两个绑定相同则提示。
- 保存即写 UserDefaults 并通知 HotkeyManager 重载。
- 显示器热插拔：监听 `NSApplication.didChangeScreenParametersNotification`，刷新 ArrangementView 与绑定重映射。

### 版本与打包

- 版本号升到 **1.1**（build.sh 的 VERSION、Info.plist）。
- 打包流程不变（swiftc 分架构 + lipo + hdiutil）。

## 注意

- v1.0 的 `⌘⌃→` 语义从「下一块屏」变为「向右相邻屏」；两屏并排时行为一致，向后兼容良好。
